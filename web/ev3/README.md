# OpenEV3 Workbench

Browser front end for the LEGO Mindstorms EV3 on its stock firmware. Open `index.html`
in Chrome or Edge, or use the hosted copy on the OpenMindstorms server.

| Section | What it does |
| --- | --- |
| **Connect** | USB (WebHID, no driver on any OS), Bluetooth (Web Serial on the paired *outgoing* COM port), or the built-in simulator. Shows name, firmware, battery, volume, sleep timer, attached devices; rename the brick; self test |
| **Program** | EV3-G style block editor. Blocks compile to lms2012 bytecode in the browser. *Run now* sends the program as a direct command (one beam, up to 1 KB); *Upload* writes an `.rbf` under `../prjs/OpenEV3/` so the program appears in the brick's own file menu, and can start it. The generated bytecode listing is shown under the editor. The Python pill links to Pybricks |
| **Control** | Motors A-D (power, run-for-degrees, brake/coast, live position); Drive panel steering two motors in sync; tone, sound files, status light, volume, display text, brick buttons; sensors on ports 1-4 auto-detected with live readout |
| **Files** | Browse `../prjs`, upload, download, delete, make folders; run `.rbf` programs and play `.rsf` sounds from the list |
| **Console** | Every message in hex, raw direct-command sender |

Keys 1-5 switch sections; `index.html#control` opens a section directly.

## How the blocks compile

`js/blocks.js` walks the Blockly workspace and emits opcodes through `js/asm.js`
(labels, jump fix-ups, a global-variable allocator). Every value is a float global;
booleans are byte globals. Sensors are read with `INPUT_DEVICE READY_SI`, motors with
`OUTPUT_STEP_SYNC` / `OUTPUT_TIME_SYNC` (steering) and `OUTPUT_STEP_SPEED` /
`OUTPUT_TIME_SPEED` (single motors). Each extra *also run at the same time* beam becomes
a VM thread started with `OBJECT_START`, which is why those programs need Upload rather
than Run now.

The protocol code in `js/` is a port of `python/openev3` and shares its tests
(`node web/ev3/tests/run.js`). `tests/blocks-smoke.html` compiles every example and
every toolbox block and runs them in the simulator VM; `tests/browser-smoke.html`
exercises the brick API against the simulator. Both are meant for headless Edge.
