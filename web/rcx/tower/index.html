Build your own RCX infrared tower

A replacement for the LEGO infrared tower, built from a Teensy 4.x or ESP32 you may already have, one 940 nm IR LED and one 38 kHz IR receiver module. The PC sees a plain USB serial port, so it works with the OpenRCX Workbench, with the rcx command-line tool, and with BricxCC and NQC on 64-bit Windows or anything else that knows how to drive a LEGO serial tower.

Why

The RCX talks over infrared at 2400 baud, 8 data bits, odd parity, 1 stop bit. A 0 bit is 417 µs of 38 kHz carrier, a 1 bit is 417 µs of darkness. The LEGO serial tower is just a modulator and demodulator on an RS-232 port. The LEGO USB tower needs a kernel driver that LEGO only ever shipped for 32-bit Windows, which is why a Windows XP virtual machine has been the usual workaround.

If you still have a LEGO serial tower, use it: it needs no driver work and the Workbench defaults to it. This board is for everyone whose tower was the USB one, or who has no tower at all.

Wiring (Teensy 4.0 default pins)

The receiver's output idles high and goes low while carrier is present, which is exactly a UART signal, so it goes straight into a hardware UART RX pin set to 2400 8-O-1. The 38 kHz carrier comes from a hardware PWM channel switched by the transistor; the LED draws around 100 mA peak at 50 % duty and is off between packets.

Pins are #defines at the top of the sketch. Mount the LED and the receiver side by side pointing the same way. Work 5 to 50 cm from the RCX's IR window and shade both ends from sunlight and bright incandescent lamps; that is the number-one cause of failed downloads with the LEGO towers too. The on-board LED blinks three times at power-up and flashes on IR activity.

Build and flash

  • Arduino IDE with Teensyduino: open OpenRCX_Tower.ino, board Teensy 4.0, USB Type Serial, upload.
  • Visual Micro: open the folder as an Arduino project, same settings.
  • arduino-cli: 
    arduino-cli compile --fqbn teensy:avr:teensy40 tower/OpenRCX_Tower
arduino-cli upload  --fqbn teensy:avr:teensy40 -p COMx tower/OpenRCX_Tower
    ESP32-S3 with native USB: --fqbn esp32:esp32:esp32s3:CDCOnBoot=cdc.

On a PC with Windows Smart App Control enforced, the Teensy toolchain's unsigned linker (collect2.exe) is blocked, so the build compiles but fails to link. The ESP32 toolchain is not affected. Build the Teensy image on another PC, or allow the toolchain.

Then plug the board in, open the OpenRCX Workbench, choose OpenRCX DIY tower and press Connect. No driver is needed: Teensy and ESP32 boards use Windows' built-in USB serial driver.

Options at the top of the sketch

DefineDefaultMeaning
CARRIER_HZ38000IR carrier. The RCX 2.0 brick's receiver is reportedly tuned for 76 kHz, but every RCX revision accepts 38 kHz (that is all the serial tower can do). Try 76000 only if range is poor
ECHO_MODE00 swallows the echo of our own LED that the receiver inevitably hears; 1 passes it to the PC like a real serial tower would
TX_BUFFER_SIZE4096Host-to-IR buffer. A firmware block packet is about 415 bytes

How it works

  • Transmit: bytes from USB are queued; each is bit-banged as an 11-bit frame (start, 8 data, odd parity, stop) with timing referenced to the frame start so rounding never accumulates. The carrier itself comes from hardware PWM (Teensy analogWrite, ESP32 LEDC), simply switched on for 0 bits and off for 1 bits.
  • Receive: the receiver module's output is already a clean UART waveform, so a hardware UART at 2400 8-O-1 reads it and the bytes are forwarded to USB.
  • Echo suppression: every transmitted byte is remembered for 20 ms. Received bytes that match the head of that queue are dropped; the first mismatch stops the filtering, so a genuine RCX reply is never eaten.

Testing without an RCX

Open the COM port with any terminal program at any baud and type: the activity LED should flash, and the IR LED shows as a faint purple flicker on a phone camera. With ECHO_MODE 1 the characters you type come back to you through the receiver, which checks the whole optical path.

With a real RCX in front of the tower, rcx -p COMx ping from the command-line tool should answer within one retry, and the Workbench's Connect shows the ROM and firmware versions.
